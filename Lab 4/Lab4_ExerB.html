Twelve faults, found and fixed

Lab 4 · Exercise B · CSS debugging

The fault list

Line numbers refer to the original file as it was handed out. Six of the twelve faults produced no visible error at all — the page simply looked wrong, which is what makes CSS debugging different from markup debugging.

Every fault was reproduced, corrected and re-checked in the browser and in the W3C validator.
Line What the file said Why it failed The correction
7 <style> opened after </head> Invalid HTML5: a style element belongs in the head Moved the whole block into <head>
12 .card h3 { color: #0f3d5c } No element inside the card is an h3 child of .card in the markup, so the rule matched nothing Selector rewritten as .fix-card h3, matching the heading that actually exists in the markup
18 font-size: 16 No unit: lengths in CSS need px, rem, % and friends font-size: 16px;
19 colour: #b03a2e; There is no colour property in CSS; the browser silently ignores it color: #b03a2e;
24 margin: 10px 20px with no semicolon The next declaration was glued to this one and both were discarded Added the ; and checked every other line for the same slip
31 backgroud-color: #e8f4fd; Misspelt property; harmless to the page, fatal to the style background-color: #e8f4fd;
36 Rule block never closed — no } Every following rule was read as part of that block, so most of the sheet stopped working Closed the block; the sheet then parsed from top to bottom
44 id="box" used on three cards An id must be unique, and duplicate ids fail validation Changed to class="fix-card" on all three, then .fix-card.highlight for the odd one out
52 a:hover written before a:link With equal specificity the later rule wins, so the plain link colour overrode the hover Reordered to link, visited, hover, active
57 <link rel="stylesheet"> inside <body> Link elements belong in the head; in the body they trigger validation errors and a flash of unstyled content Moved to the head, and the file is now embedded instead
63 box-sizing: borderbox; Not a valid value, so the declaration was ignored and widths grew by the padding box-sizing: border-box;
70 <img src="logo.png"> with no alt Missing alternative text is an accessibility failure and a validation error Replaced by a text heading, which needs no alt text at all

RM 2.80

Two of the faults, side by side

/* line 18 and 19 of the original */
.card h3 { font-size: 16
           colour: #b03a2e }

/* corrected */
.fix-card h3 {
    font-size: 1.05rem;
    color: #0f3d5c;
}

Both versions are still valid HTML. The difference only shows up in the browser, which is exactly why the W3C markup validator needs a partner: the CSS validator at jigsaw.w3.org/css-validator catches the spelling and unit mistakes that the markup checker cannot see.
