## ➕ Adding a new page

1. Drop the file into a lab folder, e.g. `Lab 1/lab3.html` — case matters, and
   spaces in names become `%20` in the URL.
2. Commit it to **`main`** (directly, or by merging a pull request).
3. That's it. The **Sync site index and README** workflow runs automatically,
   adds a card and a table row, and asks GitHub to rebuild the site (~1 minute).

Optional polish: open [`pages.json`](pages.json) and set a nicer `title`,
`description` or `tag` for the new file, then push again. That file is the only
place curation lives — the generator never overwrites an existing entry.

Everything between the `AUTO:...` markers in `index.html` and this README is
generated. To run the same step locally:

```bash
python3 tools/sync_site.py
```

## 🚀 Publishing (GitHub Pages)

Everything needed to serve the site is already in this repository. The one
remaining step is switching Pages on, which **only the repository owner can do**
— the API refuses it for app/integration tokens (`403 Resource not accessible by
integration`). Until then the URL above shows GitHub's *"There isn't a GitHub
Pages site here"* 404 page.

Open <https://github.com/seanneol88/S79146_CSF3133_K3/settings/pages> and pick
either option:

### Option A — deploy from the `main` branch (simplest)

1. **Build and deployment → Source**: *Deploy from a branch*
2. **Branch**: `main`, **folder**: `/ (root)` → **Save**

GitHub publishes the site itself within a minute; no further clicks needed.
Nothing runs from Actions in this mode.

### Option B — deploy with the included workflow

1. **Build and deployment → Source**: *GitHub Actions*
2. **Actions → Deploy to GitHub Pages → Run workflow**

The workflow then rebuilds and redeploys the site on every push to `main`.

> The workflow checks the Pages settings before doing anything:
> not enabled → it skips with a green run and prints these instructions;
> branch mode → it skips because GitHub is already publishing;
> Actions mode → it deploys. It never leaves a red ✗ on `main`.

cd S79146_CSF3133_K3

## 📝 Notes

- `Lab 1/lab1.html` loads its image from `via.placeholder.com`; if that host is
  unreachable the page shows the alt text instead.
- `Lab 3/lab3.html` posts to `send.html`, which is not part of this repository,
  so submitting the form returns a 404. The form controls and the inline sum
  calculator work normally.
- The Lab 3 pages were saved from a Cloudflare-hosted site, so they still carry
  its `beacon.min.js` analytics script and, in `lab3.html`, an obfuscated
  `/cdn-cgi/l/email-protection` link that displays as "[email protected]" once
  the decoder script 404s. Both are harmless leftovers, not part of the
  exercise.
- `Lab 3/intro5_broken.html` is invalid **on purpose** — the lab manual asks you
  to upload it first and read the validator's complaint (`<!DOCTYPE>` without
  `html`). `Lab 3/intro5.html` is the corrected version of the same page, so the
  two sit side by side with their validation screenshots.
- `Lab 2/lab2.html` and `Lab 2/form.html` post to `submit_form.php`, which is
  not part of this repository, so submitting those forms returns a 404. The
  form controls themselves render and behave normally.
- **Lab 4** follows the two problems in the Lab Exercise 4 handout.
  `Lab 4/style.css` styles Problem A (`lab4_ExerA.html`, the Visit Terengganu
  tourism page) and `Lab 4/cafe.css` styles Problem B (`lab4_ExerB.html`, the
  e-Café Campus page). Problem A also keeps a small internal `<style>` block,
  because the handout asks for internal *and* external CSS; Problem B's nav
  styles were moved out of the page into `cafe.css`.
- The `<video>` on both Lab 4 pages uses a public sample MP4 so it actually
  plays; swap the `src` for your own clip when you have one.
- Both Lab 4 pages post their forms to `action="#"`, so submitting simply
  reloads the page — there is no server behind them.
- The Lab 2 pages were copied back from the
  [University-Source-Code](https://github.com/seanneol88/University-Source-Code/tree/main/Lab%202%20Web%20Design)
  portfolio on 4 November 2026, so both repositories now carry the same files.
